# 📝 2 SUM -  [(LeetCode 1)](https://leetcode.com/problems/two-sum/)

---

## 🔷 Problem Statement (LeetCode 1)

Given an array `nums[]` and an integer `target`, return indices of **two numbers** such that:

```
nums[i] + nums[j] = target
and i ≠ j
```


### 🔎 Example Test Cases

#### Test Case 1:

```
Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: nums[0] + nums[1] = 2 + 7 = 9
```

#### Test Case 2:

```
Input: nums = [3,2,4], target = 6
Output: [1,2]
```

#### Test Case 3:

```
Input: nums = [3,3], target = 6
Output: [0,1]
```


---

# 1️⃣ Brute Force Approach

### 💡 Core Idea:

Check **every possible pair**.

### 🧠 Logic:

* Use two nested loops.
* For each element, check all elements after it.
* If sum == target → return indices.

### ⏱ Time Complexity:

```
O(n²)
```

### 🗂 Space Complexity:

```
O(1)
```

### 💻 Java Code:

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        
        for(int i = 0; i < nums.length; i++) {
            for(int j = i + 1; j < nums.length; j++) {
                
                if(nums[i] + nums[j] == target) {
                    return new int[]{i, j};
                }
            }
        }
        
        return new int[]{};
    }
}
```

### 📌 When to Use?

* Very small input size
* Quick implementation in interview if optimization not asked

# 2️⃣ Better Approach (Sorting + Two Pointers)

### 💡 Core Idea:

Sort the array and use **two pointers**

⚠ Problem: Sorting changes indices
👉 So store value + original index

---

### 🧠 Logic Steps:

1. Store value and index in 2D array:

   ```
   arr[i][0] = value
   arr[i][1] = index
   ```

2. Sort based on value

3. Use:

   ```
   left = 0
   right = n - 1
   ```

4. If sum < target → left++
   If sum > target → right--
   If sum == target → return indices

---

### ⏱ Time Complexity:

```
O(n log n)  (due to sorting)
```

### 🗂 Space Complexity:

```
O(n)
```

---

### 💻 Java Code:

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int target) {

        int n = nums.length;
        int[][] arr = new int[n][2];

        // Step 1: Store value + index
        for(int i = 0; i < n; i++) {
            arr[i][0] = nums[i];
            arr[i][1] = i;
        }

        // Step 2: Sort based on value
        Arrays.sort(arr, (a, b) -> a[0] - b[0]);

        // Step 3: Two pointer
        int left = 0;
        int right = n - 1;

        while(left < right) {
            int sum = arr[left][0] + arr[right][0];

            if(sum == target) {
                return new int[]{arr[left][1], arr[right][1]};
            }
            else if(sum < target) {
                left++;
            }
            else {
                right--;
            }
        }

        return new int[]{};
    }
}
```

---

### 📌 Why It Works?

Because sorting allows us to:

* Increase sum by moving left pointer
* Decrease sum by moving right pointer

Monotonic movement → efficient

# 3️⃣ Optimal Approach (HashMap — Most Asked)

### 💡 Core Idea:

Use a HashMap to store:

```
value → index
```

Instead of searching whole array,
directly check if complement exists.

---

### 🧠 Logic:

For each element:

```
complement = target - nums[i]
```

If complement exists in map → return
Else store current element in map

---

### ⚡ Why It’s Optimal?

* Lookup in HashMap is O(1)
* Only one pass required

---

### ⏱ Time Complexity:

```
O(n)
```

### 🗂 Space Complexity:

```
O(n)
```

---

### 💻 Java Code:

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        
        HashMap<Integer, Integer> map = new HashMap<>();
        
        for(int i = 0; i < nums.length; i++) {
            
            int complement = target - nums[i];
            
            if(map.containsKey(complement)) {
                return new int[]{map.get(complement), i};
            }
            
            map.put(nums[i], i);
        }
        
        return new int[]{};
    }
}
```

# 🎯 Important Interview Points

✔ Why do we check map before inserting?
→ To avoid using same element twice

✔ Why not sort directly?
→ Because original indices required

✔ What if multiple answers exist?
→ Clarify with interviewer

✔ Can we solve without extra space?
→ Yes, but time increases (Brute)
